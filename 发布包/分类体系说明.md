# 元件分类体系说明

## 固定、两级、版本化

目录分类使用固定的两级稳定 ID：

```json
{
  "majorCategoryId": "passives",
  "majorCategory": "电容 / 电阻 / 电感",
  "subCategoryId": "chip-resistor",
  "subCategory": "贴片电阻",
  "category": "贴片电阻"
}
```

- `majorCategoryId` 和 `subCategoryId` 是 SQLite、JSON 快照和本地 API 的稳定契约。
- `category` 是过渡期兼容显示字段，始终由 `subCategoryId` 推导，不能作为自由文本分类来源。
- 写入未知 ID、或大类和子类不匹配的组合会被拒绝。
- 旧 CSV/API 只有 `category` 时，仅支持由兼容别名表确定性映射；无法映射的文本不会创建新分类。

## 大类

1. `passives` — 电容 / 电阻 / 电感
2. `mcu-logic` — 微控制器 / 逻辑器件
3. `diodes-transistors` — 二极管 / 晶体管
4. `protection-power` — 板级电路保护 / 电源管理
5. `interface-timing` — 接口芯片 / 时钟和计时
6. `connectors-switches` — 连接器 / 端子 / 开关
7. `data-rf` — 数据转换芯片 / 射频无线
8. `opto-display` — 光电器件 / 显示模块
9. `filters-oscillators` — 滤波器 / 晶体 / 振荡器
10. `memory-sensors-isolation` — 存储器 / 传感器 / 隔离器件
11. `relays-audio-motors` — 继电器 / 蜂鸣器 / 马达
12. `modules-communication` — 功能模块 / 通信模块
13. `amplifiers-development` — 放大器 / 开发板
14. `other` — 其他（`uncategorized` 仅用于待人工复核的未分类项）

子类定义由 Core 中版本化分类表提供，并在快照元数据和 `GET /taxonomy/categories` 中公开。

## 使用方式

- 首页先选大类，再在上下文子类列表中筛选；两个级别均有明确的“全部”。
- 编辑器先选大类；切换大类会重置不属于该大类的子类。
- 搜索 API 可使用 `majorCategoryId` 与 `subCategoryId`：

```text
GET /components/search?majorCategoryId=protection-power&subCategoryId=ldo
```

## 迁移预览

现有目录行不会因启用分类体系自动改写。本仓库不包含批量迁移工具；如需迁移，必须先生成只读映射建议、人工审阅并备份（`catalog.db` 与 `catalog.json`）后再写回 live rows。

## 典型映射

- `贴片电容`、`C1` + 0603 → `passives/mlcc`
- `贴片电阻`、`电阻` + 0603 → `passives/chip-resistor`
- `STM32F103C8T6` → `mcu-logic/mcu-mpu-soc`
- `AMS1117` → `protection-power/ldo`
- `Type-C` → `connectors-switches/usb-connector`

型号和值始终与封装分开保存：例如 `partNumber=100nF`、`package=0603`，绝不将封装拼入型号。
